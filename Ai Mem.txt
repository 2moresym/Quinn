Project: Quinn, a local-only GNOME AI command assistant.

ARCHITECTURE
- GNOME Shell extension is GJS/JS only.
- Rust quinn-daemon owns Needle inference, app grounding, voice backend, and tool execution.
- UI talks to daemon over the session D-Bus.
- D-Bus name: org.quinn.Assistant
- Object path: /org/quinn/Assistant
- Interface: org.quinn.Assistant
- Ask(query: string) -> (response: string, tool_calls: JSON string)
- Listen() -> text transcript; transcript goes through the same Ask/query pipeline as typed input.
- Signal: ToolExecuted(name, args, result)
- Property: Ready: bool

MODEL
- Use Needle v2, not the old v1-only plan.
- Current needle-rs release verified: v0.2.1.
- Rust API: needle_infer::v2_engine::V2Engine.
- Model file: Cactus-Compute/needle2/needle2.cact (~13.7 MB).
- Default local path: ~/.local/share/quinn/weights/needle2.cact
- Override with QUINN_MODEL.
- Model runtime is pure Rust; no Python runtime dependency after model download.
- Needle should route intent/tool calls; deterministic local backends should resolve machine-specific entities.

APP GROUNDING
- quinn-daemon/src/apps.rs discovers visible .desktop files from user/system application directories at startup.
- AppCatalog stores desktop ID, display name, GenericName, aliases, and source path.
- Resolution prefers exact alias, then prefix/substring matches.
- open_application resolves the model's requested app through AppCatalog and launches the canonical desktop ID via gtk-launch.
- quinn-daemon/src/app_classifier.rs classifies app type from desktop metadata/capabilities.
- Signals currently considered: GenericName, Categories, Keywords, MimeType, and URL/MIME handlers.
- Browser classification recognizes WebBrowser category, http/https handlers, and text/html support, so a browser such as Helium can be identified from its installed desktop metadata instead of being hardcoded.
- Generic type resolution supports browser, chat, editor, terminal, file manager, media player, image viewer, game, development, and office.
- If a generic type has multiple candidates, the current tool path refuses to silently choose and returns the candidates.
- Future: persist user preferences (for example preferred browser), refresh the catalog when apps change, and improve fuzzy scoring/localized desktop fields.

VOICE
- quinn-daemon/src/voice.rs now provides the first optional offline voice backend.
- Feature flag: cargo build -p quinn-daemon --features voice
- STT candidate selected for first implementation: Rust `vosk` 0.3.1.
- Microphone capture uses CPAL 0.15, converts channels to mono, resamples to 16 kHz, then sends PCM i16 to Vosk.
- Default Vosk model path: ~/.local/share/quinn/voice-model
- Override model path with QUINN_STT_MODEL.
- D-Bus Listen() captures a short utterance and returns text.
- GNOME popup has a microphone button that calls Listen(), inserts the transcript into the text field, and then calls Ask().
- Default build keeps voice optional so normal CI/text builds do not require libvosk.
- Voice is NOT yet runtime-tested on the target machine.
- Future: push-to-talk/toggle recording, VAD/silence stopping, model bootstrap, live recording UI, and acknowledgment sounds.

IMPORTANT DESIGN RULES
- Local-only: no cloud/API calls.
- No Python at runtime.
- Keep GNOME extension thin; Rust owns inference/tools/voice.
- One utterance should normally become one tool call; split obvious multi-command input first.
- Never blindly execute low-confidence tool calls.
- Machine-specific entities should be grounded by local deterministic backends, not guessed from model memory.
- Do not hardcode individual applications when installed metadata/capabilities can establish their type.
- Do not silently choose between multiple apps for a generic type without a stored preference.
